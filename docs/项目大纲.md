## 1. 项目定位

个人自用的 A 股主板监控工具：

- **盘中**：轮询自选股/持仓股行情，触达建仓区间、止损、止盈时推送飞书/邮件。
- **盘后**：规则扫描全主板，生成候选池；AI 对少量候选做基本面、公告、推荐理由和止盈止损分析。
- **决策**：AI 只给计划，人工确认后生效；监控链路不依赖 AI。

> 演进方向（草案）：后续对外多人访问时，产品收敛为「自选 + 价格/异动提醒 + 个股 AI 分析报告」，持仓成本与个人盈亏移出核心。详见 `docs/产品演进-多人版.md`。

## 2. 技术架构

```
浏览器
  │
  ▼
FastAPI + Jinja2 + HTMX + ECharts
  │
  ├── 页面路由 / API
  ├── 行情服务（腾讯 / 新浪，多源降级 + 缓存）
  ├── AkShare（日线 / 财务 / 公告 / 交易日历）
  ├── SQLite + SQLAlchemy（下一阶段）
  ├── APScheduler（下一阶段）
  ├── DeepSeek（下一阶段）
  └── 飞书 / SMTP（下一阶段）
```

### 为什么选 Python

- 数据源、指标、AI、Web 生态完整；
- 几十只股票、分钟级轮询，Python 性能足够；
- C++ 会显著增加数据解析、依赖管理和迭代成本，不适合当前规模。

### 为什么数据库先用 SQLite

- 单用户、单机、数据量小；
- 零运维、文件级备份，Windows/Linux 都能跑；
- 通过 SQLAlchemy 抽象，后续可平滑迁移 PostgreSQL/MySQL；
- 内存数据库不适合需要历史行情与复盘留存的场景。

## 5. 数据源策略

| 数据 | 来源 | 说明 |
|---|---|---|
| 实时快照 | 腾讯 `qt.gtimg.cn` | 批量、GBK、无需鉴权 |
| 实时快照备用 | 新浪 `hq.sinajs.cn` | 需要 Referer，GBK |
| 日线 | AkShare `stock_zh_a_hist` | 前复权，盘后采集 |
| 财务 | AkShare 财务指标接口 | 最近 4~8 个季度 |
| 公告 | AkShare 公告接口 | 最近 30 天 |
| 交易日历 | AkShare `tool_trade_date_hist_sina` | 禁止用周末代替 |
| 指数 | AkShare `stock_zh_index_daily` | 市场风格判定 |

**结论：腾讯/新浪实时接口只提供快照，不提供完整日线与财报；日线、财务、公告必须走 AkShare。**

### 预警实现要点

- 规则由持仓（硬止损、移动止盈、止盈一/二）和自选（建仓区间、涨跌幅异动）自动生成，存在 `alert_rule`。
- 状态机字段保存在 `alert_rule.params["state"]`：连续确认次数、是否武装、上次触发时间，重启不丢。
- `STOP_LOSS` 默认 1 次确认，其余默认 2 次；冷却 30 分钟；价格反向恢复超过 0.5% 才重新武装。
- `dedup_key = code:rule:date:序号`，同一触发不会重复入库；重试只针对 `pending/failed` 事件。
- 盘中 09:30–11:30、13:00–15:00 每 120 秒轮询；集合竞价只记录不告警。
- 手动试跑：`python scripts/monitor_once.py --dry-run`；真实推送加 `--send`。

### 全市场发现实现要点

- 行情：腾讯批量接口，400 只/请求、6 线程；3195 只约 8 个请求，实测 2–4 秒。
- 日线：首次 3195 只全量回补约 8 分钟（一次性）；日常用收盘快照拼出当日 K 线，约 2–4 秒，不再逐只请求。
- 漏斗：快照阶段先淘汰，只有进入趋势阶段的股票才加载日线；全市场发现实测 4–12 秒。
- 指标按需计算：`StockContext` 只构建当前阶段用到的指标，避免为每只股票计算全部指标。
- 指标注册：`features.py` 的 `@feature_builder`；因子注册：`factors.py` 的 `@hard_filter` / `@scorer`。
- 成交量单位：AkShare 日线原始单位为“手”，入库时统一换算为“股”，与实时行情一致。
- AI 不参与发现：当前 `ai_call_log` 为 0；后续只对 Top 10–30 做结构化分析并做预算/缓存控制。
- 策略前端化预留：profile 是纯配置，后续可以做一个勾选式“策略选股”页面，把表单序列化成 profile 后复用同一套 pipeline。

### AI 交易计划与复盘实现要点

- 客户端 `app/services/ai.py`：调用前检查当日预算，失败也写 `ai_call_log`；key 缺失时明确报错。
- 计划生成 `app/services/plans.py`：只读候选池 Top N，输入压缩 JSON；输出强制修正止损/止盈/仓位/评级关系，保存为 `draft`。
- 人工确认：`confirmed` 后自动加入自选并绑定计划，盘中预警立即按该计划生成止损/止盈规则。
- 缓存：同股票、同交易日、同 prompt 版本复用草稿/确认计划，不重复计费。
- 复盘 `app/services/review.py`：大盘/板块资金/龙虎榜/自选/持仓/个人操作由本地数据生成确定性摘要；AI 仅补充叙述。**候选池不进入复盘。**
- 板块资金：东财行业主力净流入，按交易日缓存 30 分钟；接口限流时降级为新浪板块涨跌幅并明确标注。
- 龙虎榜：东财 `stock_lhb_detail_em`，按日缓存 1 小时；解析净买额、上榜原因。
- 个人操作：读取当日 `holding_transaction`，统计买卖笔数、已实现盈亏，并按止损/止盈/浮盈状态生成明日建议。
- 真实调用前需在 `.env` 填写 `DEEPSEEK_API_KEY`；当前测试全部使用注入的假 transport，不产生费用。

### 7.2 已发现的注意事项

1. **AkShare 股票列表很慢**：18 页分页约 50 s，必须在盘后落库并缓存，盘中不能实时调用。
2. **财务接口是中文列名**：不同接口字段命名不一致，需要独立映射层，不能直接把 DataFrame 丢给模板。
3. **公告接口优先用 `cninfo`**：按股票代码查询，返回结构稳定；备用方案是当日全量公告再过滤。
4. **腾讯接口偶发 SSL 握手超时**：实测出现过一次，多源降级已覆盖，不需要重试逻辑。
5. **指数代码必须带交易所前缀**：`sh000001` 是上证指数，`000001` 是平安银行，`to_prefixed_code` 已保留显式前缀。
