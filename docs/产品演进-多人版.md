# 产品演进：从个人盯盘工具到多人监控分析平台

> 状态：**草案，待确认**
> 日期：2026-11-11
> 前置：`价格预警.md` V2（个人版，已实现 A–E 阶段）

---

## 1. 定位调整

| | 个人版（现状） | 多人版（目标） |
|---|---|---|
| 用户 | 只有自己 | 注册用户，各自独立自选与提醒 |
| 核心 | 自选 + 持仓 + 止损止盈 + AI 计划 | **自选 + 价格/异动提醒 + 个股 AI 分析报告** |
| 持仓 | 核心模块 | **移出核心**（见 2.2） |
| 复盘 | 含个人盈亏与操作 | 公共市场复盘（大盘/板块/龙虎榜） |
| 形态 | 本地 Web，单进程 | 云服务器 + 域名 + 多用户 Web/PWA |
| AI | 个人预算 | 公共结果共享 + 按用户配额 |

一句话：**做“盯盘 + 提醒 + 个股研究报告”的信息工具，不做持仓账本，也不做代客理财。**

---

## 2. 模块取舍

### 2.1 保留并强化

| 模块 | 多人版做法 |
|---|---|
| 自选股 | 每用户独立，支持分组、排序、备注、批量导入 |
| 行情 | 全市场快照只抓一次，所有用户共享，不按用户重复请求 |
| 预警 | 价格上/下穿、涨跌幅、放量、突破 N 日新高/新低、进入 AI 买入区间 |
| 通知 | 飞书 / 邮件 / 微信 / Telegram / 浏览器推送，用户各自绑定、各自频控 |
| 个股分析 | 技术面 + 资金面 + 基本面 + 公告 + 舆情 → 结论、关键价位、风险点 |
| 市场复盘 | 大盘、板块资金、龙虎榜，**全站生成一份**，所有用户共享 |
| 候选池 | 公共发现结果；用户可订阅策略（勾选条件）而不是各跑一遍 |
| 页面分享 | 个股报告可生成公开只读链接，便于传播 |

### 2.2 移出核心（建议）

| 模块 | 处理 |
|---|---|
| 持仓成本 / 浮动盈亏 | 删除，或降级为「私密持仓」可选项（默认关闭） |
| 持仓交易流水 | 删除 |
| 个人操作复盘 | 删除，复盘只做公共市场部分 |
| 止损/止盈 | **保留为“提醒价位”**：用户或 AI 给出价位，触发提醒，但不涉及股数与成本 |
| 交易计划 | 保留为“关注计划”：买入区间 + 目标位 + 风险位，人工确认后生成提醒 |

> 这样既保住了“提醒”这个核心价值，又去掉了最重的数据录入负担。

## 3. 多用户架构改动

### 3.1 数据分层

```
公共数据（一份）                      用户数据（按 user_id 隔离）
├── stock                             ├── user
├── daily_bar                         ├── watchlist_item
├── candidate                         ├── alert_rule
├── review_report（市场复盘）          ├── alert_event
├── sector_flow / lhb 缓存             ├── notification_channel
└── stock_analysis（个股报告缓存）      ├── ai_quota / ai_call_log
                                      └── user_strategy_subscription
```

原则：**行情、指标、AI 个股报告只算一次，按代码+日期缓存；用户层只存“关注关系”和“提醒规则”。**

### 3.2 认证与隔离

- 第一版：邮箱 + 密码（argon2/bcrypt）+ 服务端 Session Cookie。
- 后续可加微信/GitHub OAuth、邮箱验证码登录。
- 所有用户表带 `user_id`，查询强制带当前用户过滤，禁止跨用户读取。
- 管理员角色：维护股票池、触发全市场发现、查看 AI 用量。

### 3.3 监控循环改造

```
每 120 秒
  ↓
1. 汇总全站被关注股票代码（去重）
2. 一次批量快照（腾讯 400/批）
3. 逐用户匹配 alert_rule
4. 命中 → 写 alert_event → 按用户渠道推送 → 频控/去重
```

N 个用户不会变成 N 倍行情请求，只增加规则匹配开销。

### 3.4 数据库

- 继续用 SQLAlchemy，**多用户阶段切 PostgreSQL**（并发写、连接池、备份）。
- 引入 Alembic 管理迁移（现在还是 `create_all`）。
- SQLite 保留给本地开发/单用户模式。

### 3.5 部署形态

```
腾讯云轻量 2C2G（Ubuntu 24.04）
├── Nginx（TLS、域名、限流）
├── uvicorn（单 worker，内网 8000）
├── PostgreSQL（本机）
├── cron/systemd timer（15:35 更新、18:00 复盘）
└── 每日备份 → 对象存储
```

> 多用户后仍有“单写者”需求（监控循环、定时任务），继续用单 uvicorn + 内部调度，不引入 Celery/Redis。规模上来后再拆。

## 4. AI 成本模型（多人版关键）

| 类型 | 生成频率 | 计费归属 |
|---|---|---|
| 个股分析报告 | 每股票每日最多 1 次，缓存复用 | 平台成本 |
| 市场复盘 | 每日 1 次，全站共享 | 平台成本 |
| 用户追问/自定义分析 | 按用户触发 | 计入用户每日配额 |
| 候选池解读 | 每日 1 次 | 平台成本 |

控制手段：按代码+日期缓存、Top N 限制、每用户每日次数上限、全局日预算、失败不计费、prompt 版本化。

估算：3000 只股票不可能全做 AI。只对「候选池 Top 30 + 用户自选」生成报告，按需排队。

| 项目 | 可借鉴 | 不照搬 |

| [daily_stock_analysis](https://github.com/ZhuLinsen/daily_stock_analysis) | 每日 AI 决策仪表盘、多渠道推送、零成本定时运行、Web 工作台 | 全市场全量 AI（成本高） |

| [StockGoose](https://github.com/DJChanahCJD/StockGoose) | 纯前端、无账号、本地自选，游客体验轻 | 无后端（多人必须后端） |

## 7. 风险与边界

1. **合规**：公开给他人提供“买入区间/目标价”，可能被认定为证券投资咨询。定位必须是“数据与信息工具”，全站标注“不构成投资建议”，不承诺收益、不代客操作、不收费荐股。
2. **数据授权**：腾讯/新浪/东财接口面向个人使用，公开商用存在条款风险；用户量上来后需评估正式数据源。
3. **成本**：AI 与行情请求必须共享缓存，否则用户数增长会线性放大成本。
4. **安全**：公网必须有账号体系、HTTPS、登录限流、密码策略；管理接口单独鉴权。
5. **可用性**：单机部署，断网/重启会漏推送；需要健康检查与错过补偿（启动时补跑当日任务）。

## 8. 已确认的决策（2026-11-11）

| 问题 | 决策 |
|---|---|
| 持仓模块 | **代码保留，默认关闭**（`FEATURE_HOLDINGS=false`），单用户模式可手动开启 |
| 用户规模 | 长期不超过 10 人（自己 + 朋友），**不做公开注册运营** |
| 第一版范围 | **仍然只做个人版**；先借鉴开源项目补齐功能，不急于加登录 |
| 通知渠道 | **飞书优先**；邮件作为兜底；微信/Telegram/PWA 后续再评估 |
| 访问方式 | **游客只读，不做登录验证**（内网/Tailscale + 分享链接即可） |

### 8.1 由此产生的调整

- 多用户改造整体**推迟**，等个人版功能补齐后再做。
- 因不做登录，公网暴露仍需谨慎：优先 Tailscale；若上域名，用 Nginx Basic Auth + IP 限流兜底。
- 自选/提醒仍按「单用户」存储，但表结构预留 `user_id`（默认 1），避免以后大改。
- 个股报告页可直接公开分享（无敏感数据，符合游客访问决策）。
- 持仓相关页面在默认配置下从导航隐藏，接口保留但不注册路由（或返回 403）。
